# Astro 博客重建实施计划

## 目标
在空目录 C:\Projects\astro-blog 从零搭建 Astro 7 静态博客，完整迁移 blogdev 的 10 篇文章与全部自定义功能，开发一套"现代简洁+克制二次元"的新主题。部署（新仓库/Pages 设置）按用户要求延后，但工作流文件先就位。

## 技术栈（全部经官方文档核实）
astro@^7.3.1（纯静态）、@tailwindcss/vite + tailwindcss v4 + @tailwindcss/typography、@astrojs/rss 4 / sitemap 3.7 / mdx 8、astro-icon + @iconify-json/material-symbols（构建期内联 SVG，对应配置文件里的 Material Symbols 图标名，零字体体积）、pagefind 1.5.2 extended（内建中日文分词）。包管理 npm，Node 24（fnm，shell 内 `eval "$(fnm env)"`）。

## 内容集合 schema（依盘点实测字段）
- `posts`（glob loader）：title str / date coerce.date / updated? / tags str[] / categories str[] / keywords? str[] / description? str / **skin? enum['imas-album']**（替代旧 custom_css）
- `resources`（file loader + csv-parse，复刻 lib/resource-data.js 的 BOM/唯一性/状态白名单校验）：16 字段，状态 enum(可用/待分享/更新中/已失效)
- `shuoshuo`（file loader JSON）：host_mid/fetched_at/items[{id,title,content,images[{url,width,height}],link,like,published_at}]

## 页面清单（URL 与旧站对齐）
- `/` 首页：hero(标题/副题/描述+头像) + 最近文章 + 侧栏信息卡；文章满10篇后再启用 paginate()（旧站 per_page:10）
- `/posts/[slug]/`：Prose 正文、TOC、上一篇/下一篇、字数/阅读时长、Giscus；`<!-- more -->` 截摘要
- `/archives/` 全量按年（旧配置无分页）、`/categories/`+`/categories/[slug]/`、`/tags/`+`/tags/[slug]/`（中文→slug 映射沿用旧表）
- `/resources/`：**全量静态渲染 1642 条 + 客户端增强筛选**（企划/类型/系列/年份/格式/状态/关键词；解析 `?franchise=&type=` 深链参数与 `#resource-xxx` 锚点高亮）——旧 UI 已随主题丢失无还原负担，仅守此两个深链约定
- `/shuoshuo/` 时间线（图片 referrerpolicy=no-referrer 防 B 站防盗链）+ Giscus；`/links/` + Giscus；`/about/`；`/search/` Pagefind 自定义轻 UI；`/atom.xml`（对齐旧 feed 路径，全文输出）；sitemap 集成默认路径；404
- 交互脚本统一挂 `astro:page-load`（ClientRouter 约束，官方文档确认打包脚本全站只执行一次）

## 视觉设计（克制二次元 v1）
- 浅色为主 + class 策略暗色切换（记忆 localStorage + 通知 Giscus postMessage 同步）
- 主色：765 系樱粉作为强调点缀（链接/标签/进度条），大面积保持中性灰白面、MD3 式柔和圆角与细边框；暗色为暖灰深底
- 字体：系统 CJK 栈（不拖 CJK webfont，v1 克制），代码块 Shiki 双主题 light=one-light / dark=github-dark-dimmed（对齐旧配置）
- 二次元元素 v1 限：hero 区头像+淡樱色渐变点缀、空状态/404 的手绘感小元素、标签胶囊配色；效果满意即止，不加大立绘
- 动效：View Transitions 页面过渡 + 轻微 fade/slide，respect prefers-reduced-motion
- 图片预览用原生 <dialog> 轻实现；callout(warning/danger/success/center) 重设计为现代提示框（23 处旧用法依赖）

## 内容迁移（一次性脚本 scripts/migrate-posts.mjs + 拷贝）
1. 10 篇 md：frontmatter 规范化（custom_css→skin、剔除页面级 layout/type/comments 字段）、删除 `<!-- custom_css: ... -->` 备用注释
2. pcshurufa：16 个 `{% asset_img %}` → 相对路径 Markdown 图片，同名资源目录随迁
3. imas-hires 的 247 个绝对路径 `<img>` 与 covers 目录：原样进 public/，零改动
4. resources.csv / shuoshuo.json → src/data/（旧 source/data 冗余副本不再保留）；fetch 脚本移植改路径
5. 2025year.html / player.html / CNAME / favicon → public/
6. tools/ 三个网盘维护脚本移植改路径，npm scripts 对应保留（resources:import/apply-shares/queue、fetch:shuoshuo）

## 部署工作流（文件就位，激活延后）
.github/workflows/deploy.yml：checkout@v7 → setup-node 24 → npm ci → astro build → npx pagefind --site dist → upload-pages-artifact → deploy-pages（官方指南手动变体；因需在 build 后插入 pagefind，不用 withastro/action 整合包）。public/CNAME 保证自定义域名。git init 本地仓库 + .gitignore，远端与 Pages 设置等用户建新仓库后再配。
