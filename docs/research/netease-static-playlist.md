# 网易云纯静态歌单与音频数据源：浏览器实测

调研时间：2026-10-30（UTC 11:20–12:10）。实测浏览器 Chromium **153.0.0.0**（playwright-core 1.63 / chromium-1243），
页面源为真实线上站点 `https://blog.serinap.top/`；HTTP 侧用 curl 复验同一批端点，未登录网易云、未使用代理。
本票（issue #8）只回答「有没有可用的纯静态数据链路」，不替代 #12 的交互与视觉验收。

## 结论

- **公共 Meting 的 `type=url` 端点仍然不可用**：首/中/尾三首全部 **HTTP 404**（空响应体，CORS 头存在）。此前「歌单能读、音频 404」的结论成立，且不只是浏览器侧问题。
- **存在可用的纯静态链路**：构建期把歌单元数据固化成仓库内 JSON，运行时把 `<audio>` 指向网易云**第一方**跳转地址 `https://music.163.com/song/media/outer/url?id=<id>.mp3`。博客源 Chromium 实测：首/中/尾三首都拿到真实 `loadedmetadata`（390.19s / 254.08s / 278.76s），用户点击后 `currentTime` 正常前进。
- **73 首里 68 首当前可播，5 首不可播**：不可播曲目的跳转地址会 302 到 `music.163.com/404` 的 HTML 页面，浏览器报 `MEDIA_ERR_SRC_NOT_SUPPORTED`（`MediaError.code = 4`）。这必须由前端展示失败态，不能假装整张歌单都能播。
- **官方外链播放器 iframe 可用但不能定制**：`auto=0` 时不会自动出声，点击后正常播放（剩余时长与进度条推进）；播放器状态在跨源 iframe 内，父页面读不到、也改不了样式。
- 因此 #12 采用「构建期歌单快照 + 第一方音频跳转地址 + Video.js 10 自绘 UI」，**不下载、不分发音频**；不承诺 VIP / 地区 / 登录受限内容可播。失败一律停在原地等用户决定，不自动重试。

## 一、公共 Meting 端点：能读歌单，不能取音频

| 请求（带 `Origin: https://blog.serinap.top`） | 服务端结果 | 浏览器结果 |
| --- | --- | --- |
| `type=playlist&id=8562312822` | 200 JSON，73 条，`access-control-allow-origin: *` | `fetch` 成功，73 条；`ACAO` 不是 CORS 安全列表头，JS 读不到，但不影响跨源读取 |
| `type=url&id=548650102`（首） | **404**，`content-length: 0` | — |
| `type=url&id=1942407343`（中） | **404** | — |
| `type=url&id=1354478288`（尾） | **404** | — |
| `type=pic&id=…` | 302 → `p3.music.126.net/…jpg?param=300y300`，200 `image/jpg` | 可作封面来源（快照里已改写成第一方 URL） |

结论：公共 Meting 只能当**元数据来源**（且是第三方运行时依赖），不能当音频来源。本站不用它在运行时取数据，只在本脚本生成快照时读一次。

## 二、第一方音频跳转地址（实测可播）

`https://music.163.com/song/media/outer/url?id=<songId>.mp3` 是网易云自己的外链地址：

- 无 Referer 也可用；响应 **302** 到 `m10/m701.music.126.net/.../<hash>.mp3?vuutv=…&cdntag=…`，直链带时间戳与签名，属于短时效 URL，因此**不能写进快照**，必须每次播放时让浏览器重新解析。
- 直链主机支持 Range（`206`、`content-range`），可拖动进度。
- 在 https 页面上，302 给的是 **http** 直链。Chromium 会按「可升级混合内容」自动改用 **https** 再请求：实测网络记录里没有落到 http 请求，最终是 `https://m10.music.126.net/...` 的 `206 audio/mpeg`。同一地址的 `https` 版本单独用 curl 请求也是 206，说明升级后服务端确实可用。

### 全量 73 首探测（curl，Range 0-1023，跟随跳转）

| 结果 | 数量 | 说明 |
| --- | --- | --- |
| `302 → 206`，`audio/mpeg` | **68** | 可播 |
| `302 → 302 → 200`，`text/html;charset=utf8` | **5** | 跳到 `music.163.com/404`（107KB 的网页），浏览器里就是「格式错误」 |

## 四、官方外链播放器 iframe（第一方，但不能定制）

`https://music.163.com/outchain/player?type=0&id=8562312822&auto=0&height=430`：

- 从博客源加载成功（`iframe` `load` 事件触发；响应 200，只有 `content-security-policy: upgrade-insecure-requests`，没有 `X-Frame-Options` 或 `frame-ancestors`），歌单标题「博客」与 73 首曲目都在帧内渲染。
- `auto=0` 生效：加载后没有任何声音，控件显示播放按钮、时间 `- 0:00`。
- 自动化的受信任点击命中帧内 `#play` 后：剩余时间从 `- 06:18` 走到 `- 06:14`，进度条宽度从 `2.98%` 走到 `4.00%`，暂停按钮出现 —— 播放确实发生在第一方播放器里。
- 父页面**无法访问**：`iframe.contentDocument === null`（跨源），样式、音量、当前曲目都插不进去；帧内的媒体对象还是脱离 DOM 的 `new Audio()`，连自动化都只能读 UI 文本。
- 补充：父页面不能靠它做「文章音乐开始时暂停 BGM」之类的协调 —— 跨源帧既没有 postMessage 契约，也没有播放状态接口。

## 五、方案取舍

| 方案 | 代价与边界 | 结论 |
| --- | --- | --- |
| **构建期快照 + 第一方跳转地址 + 自绘 UI**（#12 采用） | 站点运行时只有同源 JSON 与网易云媒体请求；UI/键盘/失败态可完全按本站规范做。风险：可播性取决于网易云，跨浏览器「混合内容自动升级」未逐一验证 | 采用 |
| 官方外链 iframe | 零数据维护，但不可定制、不可协调播放、不能控制移动端尺寸与主题 | 保留为原平台回退链接的目标，不作 UI |
| 自建代理 / 重新托管音频 | 需要服务器与资源，涉及分发音乐 | 不做（本票明确禁止） |
| 运行时直连公共 Meting | 第三方 API 在读者浏览器里执行，可用性/限流/隐私都不受本站控制，且 `type=url` 已 404 | 不做 |

## 六、实现约束（写进 #12 的验收口径）

- **第三方请求边界**：读者不打开播放器时零第三方请求；播放后只有 `music.163.com`（跳转）与 `p*.music.126.net` / 媒体 CDN；歌单 JSON 为本站静态端点。不注入任何 cookie（`credentials: 'omit'`）。
- **失败提示**：歌曲不可播（版权/地区/会员）、网络失败、歌单载入失败三类文案分开；每类都给出「在网易云打开」的原平台链接。
- **不自动重试**：`error` 只展示一次失败态，不重试、不跳下一首、不循环；再次播放必须是用户点击。播放自然结束才推进队列，单曲不循环。
- **不承诺权限**：不声称全部 73 首可播，也不为不可播曲目做特殊处理（不删条目、不改歌单）。

## 七、仍未验证 / 风险

- 只有桌面 Chromium 实测；Firefox、Safari、iOS/Android 上「302 到 http 直链」是否同样自动升级为 https **未验证**。若某浏览器直接拦截该混合内容，表现会是加载失败 —— 会落到失败态，不会静默。
- 可播性随账号、地区、时间变化；上面 68/73 只是 2026-10-30 的一次快照。第一方跳转地址没有公开的稳定性承诺。
- 未验证长音频的完整播放（只验证到缓冲与时长）、弱网续播、系统媒体键。
- 网易云服务条款对第三方集成有独立约束；本结论只说明技术链路，不构成授权判断。
